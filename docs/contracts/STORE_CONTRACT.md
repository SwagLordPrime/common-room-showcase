# Common Room store contract for the next builder

Clock source: Python datetime system clock; 2026-09-11T19:08:59.297643+00:00 = 2026-09-11 14:08:59 CDT, America/Chicago.

The store is a Python library for an isolated fixture board. The approved plan and evidence/gates.json determine acceptance. This document describes the interface; it does not claim an HTTP service or a connected assistant.

## Trusted configuration

Construct Store with its SQLite path, a registry of Actor objects, explicitly named artifact roots, and optionally a fixture clock. The real transport must authenticate a session and supply the registered Actor. Passing an Actor to this library is not itself network authentication. Only configured owner identities may create authority grants. Grants name existing participants, the fixed document.count capability, an existing configured root and a bounded scope statement. Existing grants cannot be overwritten or expanded by a message.

Keep the database, backup files and artifact roots in directories owned by the operator. Database administrators can replace a database or drop its guards; the event triggers do not defend against the operator. File checks assume these roots are not concurrently replaced by another local administrator. The next board must expose specific actions, never generic SQL, a shell, filesystem browsing or arbitrary URL fetching.

## Durable requests and events

Call execute(actor, action, payload, request_id). It returns the committed event sequence and the resulting task view, or null for an authority/lounge event. A key belongs to one actor and one exact action/payload fingerprint. Repeating it returns the original receipt; changing its payload is refused. If a response is lost, retry with the same key. If a claim receipt is replayed after expiry, it describes the old lease; it does not grant a new one. Completion still checks the current fence and authority.

A successful command stores its event and receipt together under one SQLite write transaction. Failed validation commits neither. Event and receipt update/delete statements are refused by database triggers. Task views are reconstructed from ordered events and returned as detached copies. This is intentionally a small-board implementation that replays the log; no large-history performance result is claimed.

## Routing and lifecycle

Create produces a draft. Deliver is a separate action by the sender or authority owner. Only the assigned worker acknowledges and claims. Other authorized workers require explicit owner assignment; they cannot silently take a task addressed to another worker. An active lease prevents reassignment unless the owner first pauses the authority. Reassignment delivers anew and requires the next worker's acknowledgment. Every later claim has a higher fence.

Finish requires the current unexpired lease plus a readable, hash-matching artifact under the authority root. It moves the task into ready for review. Only a separately registered reviewer can accept it; acceptance checks those artifact bytes again. A rejected review or wait_decision produces a visible owner decision. Decisions and pauses in one authority do not prevent an unrelated authorized task from running. A paused or revoked authority refuses work; resume cannot undo revocation. Resuming does not resurrect an old lease.

Body text, including assertions of approval, is stored as data. The document.count capability grants no command execution. A lounge note creates an event without a runnable task. Parent depth is checked against the stored parent's authority and depth, rather than accepting a caller's claimed depth.

The default fixture claim request uses 300 seconds; the enforced allowed range is 1 through 1800. Commands are bounded at 16,384 UTF-8 bytes, body text at 4,000 characters, and artifact references at eight. These are configured limits, not live capacity measurements. The failure ceiling is two attempts, shared by explicit worker failures, rejected reviews and expired attempts. Reclaiming or reassigning expired work counts the prior failed attempt. If that exhausts the budget, the response is a waiting_decision task with no lease; the caller must check the returned state and must not start work. Pausing an already expired lease preserves its failure too. Deliberately pausing a still-current lease cancels it without calling it a failure. A new owner decision or reassignment cannot reset the failed-attempt total. Failure diagnostics are retained in the immutable event history.

## Read and recovery surface

Use task, list_tasks and poll with an authenticated registered actor. Authority membership filters the returned records. Poll scans at most the requested page (maximum 100 events), returning a global cursor even if some scanned events are hidden from that actor. Sequence gaps in a participant's filtered view do not imply lost events. The global stored log remains consecutive.

Backup and restore are operator-only library methods. SQLite's backup API copies a consistent database snapshot. Destination paths must be new, inside the source fixture directory or its subfolders; existing files are never overwritten. Restore checks the supported database version and integrity before constructing a separate Store. Backup preserves event/receipt records, lease state and artifact references; artifact bytes require their own operator-managed copy. Tests use fictional artifacts already in the configured root.

The clock is supplied by the trusted runtime. Schema version 2 adds a persisted maximum observed time, including a valid command refused after its lease has expired. The event and receipt are rolled back together on refusal, while that clock floor remains. A later host-clock rollback, process restart or database restore therefore cannot revive an expiry already observed by this store. This is not a claim that arbitrary host clock changes are harmless; maintain normal clock synchronization. The first held candidate's version 1 databases are unused fictional fixtures, not supported deployments; they are preserved on disk, and no migration or live database update is performed. Real deployment, durable artifact packaging, transport authentication and browser acceptance remain later gates.

## Strike kinds and refunds (cr-upgrade, 2026-10-01)

The failure ceiling above is unchanged: two strikes stop a task. Two optional command fields change how strikes are counted; a command that omits them behaves exactly as before, and every event log written before this change folds to the same task states, because fold() only applies the changes each event already stores.

`review` takes an optional `kind`, `substance` or `paperwork`; no kind means substance, and any other value is refused `invalid`. A rejected substance review adds a strike as before. A rejected paperwork review sends the task back for an owner decision exactly like any rejection (same status, same decision text, same retained result) but adds no strike. The task counts its paperwork returns in `paperwork_returns`; the third paperwork return on one task, and each later one, counts as a strike (failed_attempts plus one, failure_note and failed_actor recorded as for a substance rejection). An accepted review ignores the kind. The kind is recorded in `review_kind` only when the caller named it.

`resolve_decision` takes an optional boolean `refund`, with the existing `body` as the written reason. A refund removes one strike (never below zero) in the same event that returns the task to delivered, and appends {by, reason, strikes_before, strikes_after} to `refunds`; failure_note, failed_actor and failed_fence are left as recorded. Whoever may resolve that decision today may refund it (the authority owner, or the sender of a helper task on that helper). A task stopped at two strikes stays the owner's alone: a refund by anyone else is refused `budget`, and a resolve at two strikes without a refund is still refused `budget`. `reinstate` is unchanged and does not reset `paperwork_returns`.

## The room-wide switch: stop_all and resume_all (cr-upgrade, 2026-10-01)

Two keeper-only actions pause and unpause everything at once. `stop_all` {reason} requires the owner role and is refused `forbidden` for anyone else; it is refused `state` if the room is already stopped, or if the keeper has no active authority. For every active (not revoked) authority the keeper owns it appends the room's own `authority_paused` event (the same lease-release rules as a single pause: a current lease is cancelled without a failure, an expired one records its expiry) and a Lounge `note` whose body starts `STOP:`. An authority that was already paused gets the note but no new pause, so the stop does not claim it. Two facts are kept apart. Which authorities the stop paused: each pause it makes carries a `room_stop` marker {by, at, reason}, which fold() keeps on the authority as `stopped_all` until that authority is resumed. That the room is stopped: each STOP: note carries a `room_stop` record {by, at, reason, paused, already_paused} (the ids the stop paused, and the ids that were already paused), which fold() keeps on the authority as `room_stopped` until a RESUME: note, carrying `room_resume`, clears it. The banner, the STOP file, the already-stopped refusal and `resume_all` follow `room_stopped`, so a stop in which every authority was already paused, or whose authorities were later resumed one by one, can still be undone. Old events never carry either marker, so every earlier log folds to the same states.

`resume_all` {reason, optional} resumes only the authorities still carrying `stopped_all`, leaves any authority that was paused by hand or revoked as it was, clears `room_stopped`, deletes the STOP file and posts `RESUME:` notes. It is refused `state` only when the room is not stopped (no active authority carries `room_stopped`). Membership and artifact-root checks are skipped on purpose so an emergency stop cannot fail because one authority's configuration drifted. Because every authority is paused, claims, renewals and every other worker action are refused `held` while stopped.

One command appends several events under one receipt: the receipt names the last event, and the response lists every event number in `seqs`. After the commit the store writes `STOP` beside `room.sqlite` (JSON {by, at (UTC, ISO 8601), reason}) on stop and deletes it on resume; the response's `flag` says `written`, `removed` or `failed: <error>`. A failed file write never undoes the committed stop, and a replayed receipt never touches the file again. The relay refuses both actions like every other owner action.
